# Training configurations

Every JSON file here is the configuration of one training run of the paper, as resolved by
`pbg.models.pbg.train.load_config` (cluster presets, Slurm, W&B and absolute paths removed).
Relative `data.sources[].dir` paths resolve against `data_base` (env `PBG_DATA_BASE`), and
`checkpoint.dir` / `start_checkpoint` against `checkpoint_base` (env `PBG_CHECKPOINT_BASE`):
untrained parents are expected under `parents/`, trained checkpoints under `checkpoints/`.
`devices` records the hardware of the original run; `data.batch_size` is per device, so the
global batch is `batch_size` times the device count. Create parents with
`scripts/create_parent_checkpoints.py`.

| Directory | Runs |
|---|---|
| `core_scaling/stable`, `core_scaling/cooldown` | 8M–85M scaling cohort: warmup-stable runs and their WSD cooldown branches (bins 256–65537) |
| `completep` | 160M, 320M, 640M CompleteP runs; 47M and 85M MDQM9-nc models (strict release) |
| `joint` | PBG-Joint 160M (D/N 80 run, continued by the D/N 192 config) |
| `finetune` | 85M vacuum and microsolvation models |
| `mdqm9_scaling` | MDQM9-nc scaling cohort (strict MDQM9-nc release, see the main README) |
| `ablations/ladder` | ROBIN-to-PBG protocol ladder (rungs L0–L7 with atom conditioning; L8 is the prefix control) |
| `ablations/data_fraction` | simulation-depth (`frac`) and system-diversity (`sys`) ablations |
| `ablations/seeds` | training-seed replicates at D/N 48 and prefix controls |

`d1280n` run of the same size. The 49M step-71000 checkpoint was not kept; rerunning
`configs/core_scaling/stable/dipper_49m_core_bin4096_ws_scaling_d1280n.json` to step 71000 recreates it.
